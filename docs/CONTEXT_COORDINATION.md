# 多请求、上下文和中断协议 0.4

## 请求竞争

草稿计划不占用执行意图；run/resume或银行执行入口会重新检查。活动执行意图有效10分钟，暂停、结束、重规划或接管后解除。它是任务协调信息，不是账务冻结或资金预扣。SQLite写事务是最终账务并发边界。

同一用户同账户的活动任务，如果剩余转账/定时登记总额超出“余额−最低留存−有效未来承诺”，建立版本绑定冲突，相关计划进入waiting_conflict，旧授权失效。独立绿色查询可继续；付款、订阅查询和取消冻结。保留会员意图与取消请求同样产生显式冲突。已完成付款不能因后来请求而撤销，系统无法预知尚未提交的未来指令。

选择可为某一参与任务、保留会员或全部暂停；不默认FIFO或自动分配比例。选择只改变安排，未选任务暂停，选中任务仍需重新运行、授权、实时资金校验。参数/状态变化使旧冲突选择作废；同决策重试只返回原选择，不执行业务。重复开启其他冲突仍须逐项处理。

金额、对象、权限和资源可能在审批期间变化；银行持写锁重算日累计与资金，不能靠先通过黄色授权锁定旧等级。跨账户和其他用户资源先做归属校验。任务先后顺序由依赖边和用户明确选择决定。

## 上下文关联

消息使用持久化conversation_id、request_id。相同用户同request_id且完整请求相同，返回原响应；异参409。UI保存发送中的完整请求，网络响应丢失后使用原编号恢复，避免再建任务。

只查看本会话关联的本人任务（最多30项），或用户在工作台明确选中的任务及版本。不默认取系统全局最近任务。明确上下文的唯一可修改字段可以直接更新任务版本；多任务、多步骤或“转账金额/最低留存”均可能匹配时，生成10分钟澄清选项并暂停相关未完成任务。用户新消息取代旧待答澄清；过期、跨用户或旧版本选择拒绝。

- “那个改成300”：只有唯一目标字段才直接更正；旧授权失效，完成步骤与回执保留，未执行部分重新检查。
- “算了，留着吧”：唯一取消目标时记录明确保留意图，停止取消及同模板未执行查询，依赖后续付款暂停，等待新安排。
- “帮我省点钱”：只做账单分析和建议。没有取消、转账或投资的隐含授权。
- 相似付款再次表达先询问复用还是新建；“再/另外”明确新建也仍需独立授权。此语义去重不同于网络request_id幂等。
- 无上下文、复合更正、币种不明、条件或未知指代要求补充完整请求；不靠置信度强行执行。本版是受限中文语法与模型候选协作，不是任意省略语言理解器。

## 中断与动作核对

| 已有事实 | 中断后的处理 |
| --- | --- |
| 尚未执行 | 目标步骤cancelled，依赖步骤paused，旧授权失效 |
| 已完成查询 | 保留原回执，标明是原快照 |
| 付款已入账 | 保留交易；退款不在本版工具范围，需单独业务或人工处理 |
| 已取消代扣 | 保留取消事实；不能说“已保留/已恢复会员” |
| 已登记但未付款的定时转账 | 可撤销承诺；若到期执行任务已生成，一并停止其未执行部分；原登记回执不抹除 |
| 结果待核验 | 保持pending_verification，只查原回执；不猜测失败或重新付款 |
| 人工接管 | 冻结自动执行；交还记录说明，不提供强制成功或改账 |

中断不能抢占正在提交的银行事务；事务完成后先核验事实再处理。停止整个任务不改变已执行结果。停止取消但留下依赖付款时，resume不能复活旧依赖，必须新版本重规划。没有通用的数据库“反向回滚”按钮。

精简补偿是明确的受控业务：本版只实现撤销尚未付款的定时承诺。退款、恢复商户协议和真实冲正均未实现，不能把文本说明当作补偿已完成。
