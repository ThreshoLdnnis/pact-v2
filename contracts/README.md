# 共享协议目录：首次评审草案

状态：DRAFT。这里只列评审输入，尚未冻结字段、生成 SDK 或实现 API。A/B/C/D 首次共同确认后，由协议 PR 维护 JSON Schema / OpenAPI / 示例，禁止各模块各自定义同名对象。

## 两套协议

| 协议 | 目的 | 主要协作方 |
| --- | --- | --- |
| Agent Task Protocol | 候选计划、DAG、暂停恢复、审批状态、结果展示 | A/C/D，B 核对执行引用 |
| Banking Tool API | 读取沙箱、实际变账、幂等查询、回执核验 | B/C，A 调用，D 展示 |

## 必须首先确定的对象

| 对象 | 拟包含的信息 | 必须解决的问题 |
| --- | --- | --- |
| TaskPlan | plan_id、version、原始请求引用、steps、状态 | 候选计划不能自带执行权限；改参/重规划生成新版本 |
| TaskStep | step_id、工具名、严格参数、depends_on、状态 | 工具白名单、DAG 无环、依赖有效、失败/暂停语义 |
| ApprovalRequest | approval_id、主体、计划版本/步骤/参数绑定、级别、过期时间、状态 | 确认与强验证如何区分、过期/拒绝/撤销与重放如何处理 |
| ExecutionReceipt | receipt_id、银行交易引用、请求绑定、结果、时间 | 由银行后端生成；A 查询核验后才能报告成功 |
| Banking Tool request / error | 幂等键、身份上下文、严格参数、稳定错误码 | 同键同请求返回同结果，同键异参拒绝；身份不能信任模型字段 |

## Banking Tool API 拟覆盖目录

- 账户、余额、流水、收款人读取。
- 转账、交易状态查询、定时转账/未来承诺登记与执行语义。
- 订阅/代扣列表与取消。
- 执行前授权验证、约束重评估、审计关联。

具体 HTTP 路径/方法、字段、响应和错误码必须经首次接口评审确定后写入这里；本阶段不以占位接口误导实现方。

## 首次评审决策清单

- [ ] ID、版本、日期时区、金额单位统一（建议整型“分”，禁止浮点账务）。
- [ ] 绿：只读自动；黄：小额日累计 ≤1000 元转账或取消订阅需用户确认；红：日累计 >1000 元转账、挂失等需模拟强验证。团队用官方文件核对规则后记录来源。
- [ ] 确定日累计主体、自然日时区、成功/待执行交易计入口径和并发保护方式。
- [ ] 明确最低留存余额、未来资金承诺和失败后的重新评估机制；不能用旧审批绕过新状态校验。
- [ ] 明确审批主体、参数绑定、有效期、单次使用/撤销与计划版本变更规则。
- [ ] 明确幂等作用域、重复执行与超时后回执查询机制。
- [ ] 定义错误码、暂停/恢复、部分完成、失败后重规划和禁止盲目回滚交易的规则。
- [ ] 确认 A/B/C/D 使用同一套协议文件与合成示例。
- [ ] 在团队群同步首次约定，记录确认并通过协议 PR 后再实施。
